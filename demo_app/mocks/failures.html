Transient failure

Worker fails, re-enqueues with a visibility timeout (10s, 20s…), then succeeds.

  1. ✅ 202 Accepted — queued
  2. ✅ Attempt 1 failed → retry in 10s
  3. ✅ Attempt 2 failed → retry in 20s
  4. ⏳ Attempt 3 … applying
  5. ⬜ Visible in catalog

Poison command

Runtime retries 3× then moves the message to products-poison.

  1. ✅ 202 Accepted — queued
  2. ✅ Attempt 1 failed
  3. ✅ Attempt 2 failed
  4. ✅ Attempt 3 failed
  5. Moved to products-poison — never appears in catalog

The UI can only see the final state through GET /products/{id}; step-by-step progress would need a status endpoint (not in the API today) — in the first version this panel would just poll for 404 → 200 and show a timeout for poison.
